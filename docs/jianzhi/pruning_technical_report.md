# 钢轨划痕检测模型剪枝技术报告

> 任务：钢轨表面划痕目标检测（单类别 → 4类：clipping / lightband / perlage / seams）  
> 基础框架：Ultralytics YOLO11  
> 剪枝目标：在精度损失 ≤ 2%（mAP50-95）前提下，参数量削减 ≤ 20%

---

## 1. 剪枝背景与目标

### 1.1 为什么需要剪枝

深度学习模型在训练时通常过参数化（over-parameterized），许多通道/权重对最终预测贡献极低。剪枝的核心目标是：

- **降低计算量（GFLOPs）**：减少推理时的浮点运算次数，提升推理速度
- **减少内存占用（Parameters）**：缩小模型体积，便于边缘端/嵌入式设备部署
- **保持精度**：以尽可能小的精度代价换取显著的效率提升

### 1.2 剪枝约束条件

| 约束项 | 要求 |
|---|---|
| 精度损失（mAP50-95） | ≤ 2% |
| 参数量削减 | ≤ 20% |
| 模型结构 | 必须与原始推理框架兼容 |
| Fine-tune | 基于已训练 best.pt 权重进行权重迁移 + 微调 |

---

## 2. 剪枝方法：结构化通道剪枝

### 2.1 方法选择

本项目采用**结构化通道剪枝（Structured Channel Pruning）**，而非非结构化（权重稀疏化）剪枝。

| 对比项 | 结构化剪枝 ✅ | 非结构化剪枝 |
|---|---|---|
| 原理 | 删除整个卷积通道/滤波器 | 将单个权重置零 |
| 硬件加速 | 直接减少矩阵尺寸，普通 GPU/CPU 即可加速 | 需要专用稀疏计算库才能受益 |
| 实现方式 | 修改 YAML 结构配置 + 权重迁移 | 添加 mask，不改变结构 |
| 精度损失 | 相对较大，需微调恢复 | 相对较小 |
| 本项目适用性 | ✅ 可直接修改 YAML 通道数，无需额外库 | ❌ YOLO 框架不原生支持 |

### 2.2 通道重要性判断

通过 **L1 范数**衡量卷积核的重要性：

```
importance(channel_i) = Σ |W_i|   (对该通道所有权重取绝对值之和)
```

L1 范数越小 → 该通道输出对后续层贡献越弱 → 优先剪除。

实际操作时，不逐通道计算后选择，而是**按层级制定固定削减比例**（如 P3/P4 削减 12.5%），确保整体结构一致、权重迁移可控。

### 2.3 通道依赖约束

剪枝不能随意删减，相邻层之间存在严格的通道数依赖关系：

```
Conv_A (out=C₁) → BN → Conv_B (in=C₁)
```

若删除 Conv_A 的第 k 个输出通道，Conv_B 的第 k 个输入通道也必须同步删除。

对于 YOLO 结构中的 Concat 连接：

```
Concat([branch_A (C₁), branch_B (C₂)]) → in_channels = C₁ + C₂
```

任意一个分支通道变化都会影响后续层的输入维度，因此剪枝策略必须全局统一规划。

## 3. YOLO11s 结构分析

在设计剪枝方案前，需要深入理解 YOLO11s 的原始结构，找出可剪枝的空间。

### 3.1 YOLO11s 原始参数（s 规格）

```
scales: s: [depth=0.50, width=0.50, max_channels=1024]
```

- `depth`：控制 C3k2 模块的 repeats（重复次数）
- `width`：控制各层通道数（yaml 中写的通道值 × 0.50 = 实际通道数）
- 实际参数量：**9.429 M**，GFLOPs：**21.55 G**

### 3.2 各层实际通道数

| 层级 | YAML 写值 | ×width(0.50) | 实际通道数 |
|---|:---:|:---:|:---:|
| Conv0（P1） | 64 | ×0.50 | **32** |
| Conv1（P2） | 128 | ×0.50 | **64** |
| C3k2（P2） | 256 | ×0.50 | **128** |
| Conv3（P3） | 256 | ×0.50 | **128** |
| C3k2（P3） | 512 | ×0.50 | **256** |
| Conv5（P4） | 512 | ×0.50 | **256** |
| C3k2（P4） | 512 | ×0.50 | **256** |
| Conv7（P5） | 1024 | ×0.50 | **512** |
| C3k2（P5） | 1024 | ×0.50 | **512** |
| SPPF | 1024 | ×0.50 | **512** |
| C2PSA | 1024 | ×0.50 | **512** |

### 3.3 为什么不能通过减少 repeats 剪枝

YOLO11s 的 `depth=0.50` 已将所有 C3k2 模块的 repeats 压缩至**最小值 1**：

```yaml
# 原始 yolo11.yaml（depth=0.50 时 repeats 最小为 1）
- [-1, 2, C3k2, [...]]  # yaml写2 × depth(0.50) = 1（向下取整）
```

无法再通过减小深度来剪枝，**唯一可行的结构化剪枝手段是削减通道宽度（width）**。

## 4. 剪枝方案一：yolo11s 保守剪枝

### 4.1 设计理念

目标是在精度损失最小的前提下实现有效压缩。参考了 YOLOv8s 多尺度剪枝的思路：
- YOLOv8s 多尺度剪枝：保持通道宽度，仅削减 C2f repeats 深度
- 本方案同理：由于 depth 已无法削减，改为**保持深层（P5/C2PSA）完全不变，仅轻度削减中层（P3/P4）通道**

### 4.2 层级削减策略

**核心原则**：越靠近输出层的特征语义越丰富、越不可缺，应优先保留；浅中层语义冗余更高，可适当削减。

| 层级 | 原始通道 | 剪枝后通道 | 削减比例 | 原因 |
|---|:---:|:---:|:---:|---|
| P1（Conv0） | 32 | **32** | 0% | 浅层边缘/纹理特征，通道数已很少 |
| P2（Conv1） | 64 | **64** | 0% | 基础几何特征，保持完整 |
| P3 中层 C3k2 | 128 | **112** | -12.5% | 中层语义，轻度削减 |
| P3 Conv3 | 128 | **112** | -12.5% | 与 C3k2 保持一致 |
| P4 中层 C3k2 | 256 | **224** | -12.5% | 中层语义，轻度削减 |
| P4 Conv5 | 256 | **224** | -12.5% | 与 C3k2 保持一致 |
| P5 深层 C3k2 | 512 | **512** | **0%** ✓ | 深层高级语义，完整保留 |
| SPPF | 512 | **512** | **0%** ✓ | 多尺度感受野，不可削减 |
| C2PSA | 512 | **512** | **0%** ✓ | 注意力机制，完整保留 |

### 4.3 scales 设置的关键决策

```yaml
# 保守剪枝配置
scales:
  s: [1.00, 1.00, 1024]  # depth=width=1.00，yaml中通道数即为实际值（不缩放）
```

**为什么设置 scales=[1.00, 1.00, 1024] 而不是 [0.50, 0.50, 1024]？**

原因：需要手动指定通道数（P3/P4=112/224，P5=512），若 width=0.50 会自动将 yaml 值再除以 2，导致通道数不符合预期。设置 width=1.00 使得 **yaml 中写的通道数即为实际通道数**，便于精确控制。

### 4.4 Head 通道联动

削减 Backbone 通道后，Head 中的 Concat 操作自动产生联动：

```
# Concat P5(512) + P4(224) = 736  → C3k2 输出 224
- [[-1, 6], 1, Concat, [1]]        # cat backbone P4 (512 + 224 = 736)
- [-1, 1, C3k2, [224, False]]      # 13, 输出 224（跟随 P4 剪枝）

# Concat P4(224) + P3(112) = 336  → C3k2 输出 112
- [[-1, 4], 1, Concat, [1]]        # cat backbone P3 (224 + 112 = 336)
- [-1, 1, C3k2, [112, False]]      # 16, 输出 112（跟随 P3 剪枝）
```

P5 层 Head 保持 512 不变，权重可 100% 复用。

### 4.5 实测结果

| 指标 | 原始 yolo11s | 保守剪枝后 | 变化 |
|---|:---:|:---:|:---:|
| Parameters / M | 9.429 | 8.549 | ↓ **9.33%** |
| GFLOPs / G | 21.55 | 18.19 | ↓ **15.59%** |
| 权重迁移率 | — | 272 / 499 层匹配 | P5/SPPF/C2PSA 完整复用 |
| mAP@0.5 / % | 86.91 | 85.29 | ↓ **1.86%** |
| mAP@0.5:0.95 / % | 65.93 | 61.75 | ↓ **6.34%** |

> **分析**：参数量和计算量压缩达预期，但 mAP50-95 下降 6.34%，超出 2% 约束。原因是剪枝后模型容量不足，最佳 Epoch 提前出现在第 206 轮（训练提前饱和），模型未能充分拟合数据分布的细微变化。

## 5. 剪枝方案二：LSDECD-FDPN-ODConv 改进模型剪枝

### 5.1 原始改进模型结构

LSDECD-FDPN-ODConv 在 yolo11s 基础上集成了三项改进：

| 改进模块 | 位置 | 说明 |
|---|---|---|
| **C3k2_ODConv** | Backbone 全部 C3k2 | 将标准 C3k2 替换为 ODConv（全维度动态卷积）版本 |
| **FocusFeature（FDPN）** | Head 第 11、18 层 | 多尺度特征聚合，替代原始简单 Upsample+Concat |
| **Detect_LSDECD** | 检测头 | 引入 `share_conv`（DEConv_GN 可形变卷积），由 `hidc` 参数控制隐藏通道数 |

原始改进模型参数量：**10.164 M**，GFLOPs：**19.26 G**

### 5.2 剪枝方案设计

#### 5.2.1 核心思路

由于 `Detect_LSDECD` 的 `hidc` 参数在 `tasks.py` 中会被 `width` 系数自动缩放，剪枝方案必须保持 `width=0.50` 不变，才能确保 `hidc` 维持原始值 128，从而保证检测头 `share_conv` 的参数量不受影响。

因此本方案**保持 `scales: s:[0.50, 0.50, 1024]` 与原始完全一致**，利用 width 自动处理所有模块的通道缩放：

```yaml
scales:
  s: [0.50, 0.50, 1024]  # 保持原始缩放，yaml 通道值 × 0.50 = 实际通道数
```

`hidc` 的计算自动保持正常：
```
hidc = make_divisible(256 × 0.50, 8) = 128  ← 与原始完全一致 ✓
```

#### 5.2.2 通道数调整方法

由于 width=0.50 会自动将 yaml 值折半，需要在 yaml 中写**2倍目标值**：

| 层级 | 目标实际通道 | yaml 写值（÷0.5×2） | 计算 | 原始实际通道 | 变化 |
|---|:---:|:---:|:---:|:---:|:---:|
| P2 C3k2_ODConv | 112 | **224** | 224×0.50 | 128 | -12.5% |
| P3 Conv | 112 | **224** | 224×0.50 | 128 | -12.5% |
| P3 C3k2_ODConv | 224 | **448** | 448×0.50 | 256 | -12.5% |
| P4 Conv | 224 | **448** | 448×0.50 | 256 | -12.5% |
| P4 C3k2_ODConv | 224 | **448** | 448×0.50 | 256 | -12.5% |
| P5 Conv | 512 | **1024** | 1024×0.50 | 512 | **0%** ✓ |
| P5 C3k2_ODConv | 512 | **1024** | 1024×0.50 | 512 | **0%** ✓ |
| SPPF | 512 | **1024** | 1024×0.50 | 512 | **0%** ✓ |
| C2PSA | 512 | **1024** | 1024×0.50 | 512 | **0%** ✓ |

#### 5.2.3 Head 保持原始 yaml 不变

关键设计：**Head 部分（FocusFeature、Detect_LSDECD）完全不修改 yaml**，通道数由框架自动根据 Backbone 输出推导：

```yaml
# Head 与原始 LSDECD-FDPN-ODConv.yaml 完全相同，无需修改
- [[10, 6, 4], 1, FocusFeature, []]     # 输入 [512, 224, 224] → 自动计算输出 336（原 384）
- [[14, 11, 17], 1, FocusFeature, []]   # 输入 [256, 336, 128] → 自动计算输出 504（原 576）
- [[24, 18, 21], 1, Detect_LSDECD, [nc, 256]]  # hidc=256×0.50=128（与原始完全一致）✓
```

`FocusFeature` 的输出通道自动跟随 Backbone 缩减（336 < 384），但 `Detect_LSDECD` 的 `hidc` 保持 128，确保 share_conv 参数量不变。

#### 5.2.4 完整通道对照表

| 层级 | 原始实际通道 | pruned-v2 实际通道 | 变化 |
|---|:---:|:---:|:---:|
| P1 Conv0 | 32 | 32 | 不变 |
| P2 Conv1 | 64 | 64 | 不变 |
| P2 C3k2_ODConv | 128 | **112** | -12.5% |
| P3 Conv3 | 128 | **112** | -12.5% |
| P3 C3k2_ODConv | 256 | **224** | -12.5% |
| P4 Conv5 | 256 | **224** | -12.5% |
| P4 C3k2_ODConv | 256 | **224** | -12.5% |
| P5 Conv7 | 512 | 512 | **0%** ✓ |
| P5 C3k2_ODConv | 512 | 512 | **0%** ✓ |
| SPPF | 512 | 512 | **0%** ✓ |
| C2PSA | 512 | 512 | **0%** ✓ |
| FocusFeature L11 输出 | 384 | 336 | 自动缩减 |
| FocusFeature L18 输出 | 576 | 504 | 自动缩减 |
| Detect_LSDECD hidc | **128** | **128** | **完全不变** ✓ |

### 5.3 实测结果

| 指标 | 原始 LSDECD-FDPN-ODConv | pruned-v2 | 变化 |
|---|:---:|:---:|:---:|
| Parameters / M | 10.164 | 9.345 | ↓ **8.06%** |
| GFLOPs / G | 19.26 | 16.58 | ↓ **13.91%** |
| mAP@0.5 / % | 88.95 | 88.16 | ↓ **0.89%** ✅ |
| mAP@0.5:0.95 / % | 67.35 | 66.39 | ↓ **1.43%** ✅ |
| Precision / % | 87.91 | 87.66 | ↓ 0.28% |
| Recall / % | 87.70 | 85.12 | ↓ 2.94% |

精度损失均在约束范围内（mAP50-95↓1.43% < 2%），剪枝方案验证成功。

## 6. 两种剪枝方案对比

### 6.1 方案设计对比

| 对比项 | yolo11s-rail-pruned-conservative | LSDECD-FDPN-ODConv-pruned-v2 |
|---|---|---|
| 基础模型 | yolo11s（官方基线） | LSDECD-FDPN-ODConv（改进模型） |
| scales 配置 | `[1.00, 1.00, 1024]`（手动指定绝对值） | `[0.50, 0.50, 1024]`（利用 width 自动缩放） |
| 剪枝层级 | P3/P4 削减 12.5%，P5/C2PSA 完整保留 | P3/P4 削减 12.5%，P5/C2PSA 完整保留 |
| 特殊处理 | 无（标准结构） | 必须保持 width=0.50 以防止 hidc 暴增 |
| Head 处理 | 跟随 Backbone 通道手动调整 | 完全不修改，框架自动推导 |
| 参数量削减 | ↓ 9.33%（0.880M） | ↓ 8.06%（0.819M） |
| GFLOPs 削减 | ↓ 15.59%（3.36G） | ↓ 13.91%（2.68G） |
| mAP50 变化 | ↓ 1.86% | ↓ **0.89%** ✅ |
| mAP50-95 变化 | ↓ **6.34%**（超出约束！） | ↓ **1.43%** ✅ |

### 6.2 效果差异原因分析

**yolo11s 保守剪枝精度损失更大**，主要原因：

1. **基础模型容量更弱**：yolo11s 是官方标准模型，结构紧凑，12.5% 通道削减对其影响更大
2. **训练提前饱和**：最佳 Epoch 出现在第 206 轮（总计 300 轮），说明剪枝后模型容量不足，无法继续学习
3. **mAP50-95 指标更严格**：该指标反映不同 IoU 阈值下的综合表现，对模型容量更敏感

**LSDECD-FDPN-ODConv-pruned-v2 精度保留更好**，主要原因：

1. **基础模型容量更强**：改进模型带有 ODConv/FDPN/LSDECD 等增强结构，具有更强的特征表达能力，剪枝后仍有足够余量
2. **v2 修正保证了 Detect_LSDECD 不受损**：hidc 完全不变，检测头 share_conv 的参数量不减少，保持了检测头的判别能力
3. **充分训练**：最佳 Epoch 出现在第 426 轮，模型有充分时间恢复精度

## 7. 权重迁移策略

剪枝后重新训练从零开始会浪费已训练的知识，通过**权重迁移 + Fine-tune**可以大幅缩短收敛时间：

### 7.1 权重迁移规则

```python
# 迁移逻辑：名称匹配 + 形状兼容
for name, param in pruned_model.named_parameters():
    if name in original_state_dict:
        orig_param = original_state_dict[name]
        if orig_param.shape == param.shape:
            # 完全匹配：直接复用（如 P5/SPPF/C2PSA 层）
            param.data = orig_param.data
        else:
            # 形状不匹配：取前 N 个通道（如 P3/P4 层）
            slices = tuple(slice(0, s) for s in param.shape)
            param.data = orig_param.data[slices]
```

### 7.2 各层迁移情况

| 层级 | 迁移类型 | 说明 |
|---|---|---|
| P1/P2 层 | **完全复用** | 通道数不变，权重 100% 迁移 |
| P3/P4 层 | **部分复用** | 取前 112/224 个通道，保留最重要的权重 |
| P5/SPPF/C2PSA | **完全复用** | 通道数不变，权重 100% 迁移 |
| Head P5 分支 | **完全复用** | 跟随 P5 Backbone 完整保留 |
| Head P3/P4 分支 | **部分复用** | 跟随对应 Backbone 通道截取 |

### 7.3 Fine-tune 训练配置

```python
# Fine-tune 超参数配置
model.train(
    data    = '/data/.../rail_scratch.yaml',
    epochs  = 500,
    batch   = 128,
    imgsz   = 640,
    optimizer = 'SGD',
    lr0     = 0.01,        # 与原始训练保持一致
    weight_decay = 0.0005,
    device  = 0,
)
```

Fine-tune 使用与原始训练**相同的学习率和优化器**，让模型在已有权重基础上充分适应新的通道结构。

## 附录 A：YAML 配置文件关键片段

### A.1 yolo11s-rail-pruned-conservative.yaml 核心配置

```yaml
nc: 4
scales:
  s: [1.00, 1.00, 1024]  # 手动指定绝对通道数

backbone:
  - [-1, 1, Conv, [32, 3, 2]]           # P1: 32（不变）
  - [-1, 1, Conv, [64, 3, 2]]           # P2: 64（不变）
  - [-1, 1, C3k2, [112, False, 0.25]]   # P2→P3: 112（原128，-12.5%）
  - [-1, 1, Conv, [112, 3, 2]]          # P3: 112
  - [-1, 1, C3k2, [224, False, 0.25]]   # P3→P4: 224（原256，-12.5%）
  - [-1, 1, Conv, [224, 3, 2]]          # P4: 224
  - [-1, 1, C3k2, [224, True]]          # P4: 224
```
